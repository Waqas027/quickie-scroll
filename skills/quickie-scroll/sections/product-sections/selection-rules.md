# Selection rules — how the five are reasoned, not listed

*The part that decides whether the recommendation reads as bespoke or as a template. Run

## Read these eleven signals first

Every one of them is already captured by the time question 6a runs. Reading them is the
whole job; the sections fall out of the read.

| Signal | Where it is | What it changes |
|---|---|---|
| Product type | `SUBJECT` | which family of sections is even relevant |
| Industry | `SUBJECT` | the vocabulary and the proof the audience expects |
| Brand positioning | `TONE`, `BRAND_NAME` | luxury restrains, technical explains, playful demonstrates |
| Target audience | `SUBJECT`, `TONE` | a specifier wants numbers, a buyer wants feeling |
| User references | `REFS` | a product anchor makes anatomy and macro sections possible and obvious |
| Existing scenes | `CHAPTERS[]` | anything the film already showed is **out** |
| Visual language | `LOOK`, `PALETTE` | a look's grammar suits some patterns and refuses others |
| Product characteristics | the brief | parts → anatomy; surface → macro; states → transformation |
| Story opportunities | the brief | origin, craft, ecosystem — only where a real story exists |
| Sections already selected | this question | no two sections may carry the same beat |
| Desired page length | acts + `N` | five short sections or three long ones, not both |

## Product type → where to start looking

Starting points, not answers. Each still has to survive the anti-duplication pass.

| Product | Reach for | Because |
|---|---|---|
| **Perfume / fragrance** | anatomy · macro material · ingredient story · experience · final reveal | the object is small and the value is invisible — detail and origin carry it |
| **Car / vehicle** | exterior reveal · design details · interior · performance figures · engineering · final drive | the buyer walks around it, sits in it, then asks what it does |
| **Fashion / apparel** | fabric macro · craft journey · lifestyle · gallery · lookbook rail | material and wear, not specification |
| **SaaS / software** | feature expansion · interactive explorer · use-cases · before/after · ecosystem | there is no object, so behaviour *is* the product |
| **Furniture** | material story · anatomy · scale-in-room · finishes explorer · lifestyle | joinery and how it lives in a space |
| **Tech hardware** | layered breakdown · technical specs · hotspots · comparison · ecosystem | internals and integration are the argument |
| **Food / drink** | ingredient story · craft journey · macro texture · ritual/serving · lifestyle | provenance and appetite |
| **Jewellery / watches** | macro detail · anatomy · craft journey · 360° reveal · final showcase | the whole product is close-range detail |
| **Property / architecture** | environment transformation · material palette · use-cases · gallery · story | context and light, not parts |

Where the product is none of these, reason from its characteristics rather than forcing it
into a row: *does it come apart* (anatomy, breakdown) · *is its surface the point* (macro,
material) · *does it change state* (transformation, before/after) · *does it do things*
(features, hotspots, explorer) · *does it have an origin worth telling* (craft, ingredient)
· *does it live somewhere* (lifestyle, environment, ecosystem).

## The anti-duplication pass — run it before presenting

Cross off any candidate that fails one of these:

- **The film already did it.** A chapter that flew through the interior kills the interior
  section. Check every candidate against `CHAPTERS[]` by name and by beat.
- **Another candidate already carries the beat.** Anatomy and layered breakdown are the same
  idea twice; hotspots and interactive explorer overlap. Pick the stronger one.
- **The pattern repeats.** Two pinned scroll-through scenes back to back read as one broken
  section. Vary the motion across the set
  ([`animation-patterns.md`](animation-patterns.md) → *vary the pattern*).
- **It needs assets that don't exist and can't be extracted.** A 360° reveal needs a turn
  table; a comparison needs two states. If neither the chain nor the user's references can
  supply them, the section is a promise, not a section
  ([`workflow.md`](workflow.md) → *assets*).
- **It exists only to reach five.** Four excellent sections and one honest "the film plus
  the panels is already enough" beats five with a passenger — but you must genuinely have
  looked for the fifth before saying so.
- **It isn't about this product.** A generic "Why choose us" is an act, not a product
  section ([`../acts.md`](../acts.md)).

## Say why, in one line

The checklist opens with the reasoning, not with the options — *"the bottle has real
structure and the oud has a real origin, so I'd spend the page on anatomy and provenance
rather than on features"*. That sentence is what proves the recommendation was reasoned. A
list presented without it is indistinguishable from a template, however good the list is.
